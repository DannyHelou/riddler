## The schedule

`npm run schedule` (`scripts/build-schedule.ts`, logic in `lib/scheduleBuilder.ts`) rotates each tier through its own pool: warm-up 90, trap 91, boss 91. A riddle comes back only after at least 90 days (`REPEAT_GAP_DAYS` in `lib/content.ts`), so each pool must hold at least 90 riddles. Because the pools have slightly different sizes, the three rotations drift against each other and no day's trio repeats.

- Days up to and including today are never changed. `--rebuild` redoes everything (pre-launch only), `--start`/`--days` set the range, `--dry-run` prints the stats.
- New riddles join the rotation the next time you run it. More riddles per tier means a longer gap before anything repeats.
- When the launch date is set: `LAUNCH_DATE=YYYY-MM-DD npm run schedule -- --rebuild`.

## Simulator interface

```ts
export const expected: number;                    // in answer_value units
export const kind: 'probability' | 'expectation';  // ±0.5 pp or ±1% relative
export function simulate(): number | null;         // one trial; null = discard (conditioning)
```

`npm run verify` runs every sim for 10^6 kept trials and fails on any mismatch (`-- --only id1,id2` for a subset).
